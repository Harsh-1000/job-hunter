🎯 Job Hunter: how it works

A Telegram bot that watches LinkedIn for new jobs and sends each user only the ones that fit their resume and filters, with a match % and the skills they are missing.

Overview

No LinkedIn account

It uses the public jobs-guest endpoints that visitors who aren't signed in see. Nothing can get an account blocked.

Shared searches

Users with the same keyword + location + filters share one request. Each job description is fetched once and scored for everyone.

⚡ Just posted by default

Every 3 min, newest first. Only jobs ≤ 30 min old are sent (LinkedIn's "x minutes ago"); older ones are skipped before even fetching them. Users can widen to past hour / 24 h / week in Filters.

Polite by design

2–5 s between requests, retries on HTTP 429, then a 10→60 min cooldown. Scans run every 3 min, newest first.

The scan cycle

Plan

For each active user: one search per keyword × location. Identical searches merge. A user joining a search that has already run gets its recent results back-filled.

Search

LinkedIn, newest first (sortBy=DD), 10 per page. Paging stops at the first already-seen job. A brand-new search reads up to 3 pages.

Queue

Each new job becomes a waiting delivery for every user of that search.

Details

Excluded title words are rejected first, with no request. The description is fetched once and cached, up to 60 per cycle; the rest wait.

Match

Duplicate check (same role in another city), then hard filters and the score. The delivery becomes pending or rejected with a reason.

Deliver

Best score first, up to 10 per user per cycle. Paused users and quiet hours are skipped; a user who blocked the bot is auto-paused.

Changing filters or uploading a new resume re-scores recent jobs from the cache straight away, with no new LinkedIn requests.

Delivery states

waiting→ pending→ sent→ appliedsavedhidden  or rejected

Match score

score = 65 × skill coverage + 20 × title relevance + 15 × experience fit

Skill coverage · 65

Of the skills the job names (from a ~110-skill taxonomy), how many are on your resume. Skills in the title, or mentioned twice, count double. Very short descriptions are pulled toward 40%.

Title relevance · 20

Best overlap with your keywords after normalising: AI = Artificial Intelligence, GenAI = Generative AI, back-end = backend, LLM ⇒ AI. Generic words like "engineer" are ignored.

Experience fit · 15

Full marks if the job asks for ≤ your years, −30% per extra year. Years are read from text like "2-4 years", "3+ yrs", "minimum 5 years".

Resume & per-user folders

Parsing (local only)

Text: pypdf / python-docx / UTF-8. Skills: the same taxonomy as the matcher. Years: date ranges (Jan 2024 – Present, 03/2021 - 02/2023…), skipping education and merging overlaps, with "X+ years" as a fallback. Keywords: suggested from skill categories and the job titles found.

Folder per Telegram user ID

data/users/<telegram_id>/   0700
  resume.pdf             latest upload
  resume.txt.extracted   plain text
  profile.json           skills, years…

Telegram authenticates the numeric user ID, so a handler only ever reaches the sender's own folder. Non-int IDs are refused, files are 0600 and written atomically. A new upload replaces the old one, and /deleteme wipes it all.

Deploy & operate

Docker

Multi-stage build: base → test (pytest) → runtime. If a test fails, no image is built. restart: unless-stopped plus Docker enabled at boot means the bot starts on boot and after crashes. The healthcheck watches data/heartbeat.

Disk stays small

Log files rotate hourly and are deleted after 12 h. Docker logs are capped at ~2 MB. Rebuilds remove old images and build cache. The database prunes itself every 6 h.

jobhunter command

jobhunter health | logs | errors | scans
jobhunter users | approve <id> | block <id>
jobhunter restart | rebuild | update
jobhunter clean | test | env | backup

Tests & quality gates

~175 tests, no network

LinkedIn and Telegram are faked. They cover skills, filters, resume parsing, storage, matcher, LinkedIn parsing & back-off, DB, full scan cycles and bot handlers.

Run automatically

① git pre-commit & pre-push hooks · ② GitHub Actions on every push · ③ every Docker build.
